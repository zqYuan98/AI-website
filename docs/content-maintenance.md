# 内容维护约定

运行 `node scripts/check-content.mjs` 可检查博客、作品、Lab、阅读资源关联与声明的封面。完整构建会自动运行该检查；错误内容不会静默退回文件名或空摘要。

## 日期和阅读时长

YAML 日期统一加引号：`date: "2026-09-05"`、`updatedAt: "2026-09-05"`。这是为了保留原始日期字符串，防止 YAML 把不存在的日期先转换成另一天再通过校验。

博客不再手写 `readingTime`。页面按正文中的汉字和英文词近似估算，少于一分钟显示“不到 1 分钟阅读”；它是阅读提示，不是精确计时。不包含图片链接与网页地址长度，不用增加正文来凑时长。

## 基本字段

- 博客：`title`、`summary`、`date`、`placeholder` 与非空正文。
- 作品：`title`、`summary`、`role`、`period`、`placeholder`、`order`、`featured`，以及“背景 / 问题”“我做了什么”“结果与反思”三节正文。
- Lab：现有名称、摘要、问题、使用、边界、状态、精选、顺序、日期、封面、封面说明字段，以及非空正文。
- 布尔值用 `true` / `false`，不加引号；`order` 必须是非负整数。
- 文件名使用小写英文、数字和连字符；同目录不允许同名 `.md` / `.mdx`。
- `tags` 可省略；如提供则为无重复的非空字符串数组。
- 博客与作品可不提供封面；如声明 `cover`，必须是已存在的 public 文件路径。Lab 封面必填。不要填写外部链接、查询参数或 `..` 路径。

普通工具收藏与作者精选维持原有区别。每次新增 Lab 需同时提供实际页面；当前检查会拦截只有目录内容、没有可运行入口的项目。第二个实验再考虑引入统一 registry，不需要现在重写实验结构。

真实姓名不进入公开内容，继续使用“维他命”。项目口径使用“钢印 OCR 研发”。项目状态、案例证据和联系方式必须来自实际材料；当前联系入口不暗示已提供邮箱或表单。
