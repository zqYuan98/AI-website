# 资源库与个人收藏维护

## 两个入口

- `/tools`：公开资源库，默认精选，支持用途浏览、阅读内容与全库搜索。
- `/tools/manage`：本机个人管理台，仅开发环境开放。运行 `npm run dev` 后，在终端显示的 `http://127.0.0.1:端口/tools/manage` 使用。

个人管理台不提供线上账号或跨设备同步。部署后的管理页与本机 API 均返回 404；旧 `/api/local-tools` 在开发环境也停止写入，防止新增私人收藏继续进入公开文件。

## 收藏、整理、公开

1. 添加资源或导入浏览器导出的书签 HTML，先查看导入预览，再确认保存。
2. 新资源默认为「仅自己 / 待整理」。保存不会改公开网站。
3. 按用途、类型、标签和私人备注整理。常用是个人置顶偏好，与公开精选分开。
4. 要分享的条目标为公开；精选需要填写真实推荐理由。
5. 点击公开预览，检查新增、变更和撤下的条目及公开字段。
6. 点击「生成公开版本」，写入项目内的 `content/resource-library.json`。依照原有部署流程发布后，线上才生效。

将已公开条目改为仅自己或归档后，同样需要重新生成公开版本并部署才能从线上撤下。历史公开内容不会因本机编辑立即消失。

## 数据存放与边界

- 私有库默认位于用户目录下 `.vitamin-library/<项目路径哈希>/library.json`，在网站仓库之外。
- 可通过服务器环境变量 `VITAMIN_LIBRARY_DIR` 指定其他仓库外目录；不能指向项目内的 `content`、`public` 等位置。
- 私人备注、原文件夹、导入批次、个人置顶和整理状态留在私有库。公开版本只包含公开字段白名单。
- `src/lib/public-resources.ts` 是公开读取入口，首页精选、资源页和结构化数据均从它取得数据；它不读取私有库。
- 私有收藏不会为获取图标或摘要向外部服务发送网址；新增条目使用文字图标占位。公开内容继续复用已有本地图标。
- 备份按钮下载完整个人库，请保存在自己的存储位置。不要将个人备份放进网站公开目录或提交到代码仓库。

“仅自己”是本机存储与生产环境关闭所提供的隔离，不是密码保险箱或文件加密；同一个操作系统账户仍可以读取这些本地文件。

## 既有内容迁移

原有公开数据是 268 条工具（260 条参考导航导入 + 8 条短评）和 6 条阅读资料，共 274 条。这不是本轮读取的浏览器书签。

首次使用管理台时，从现有公开内容初始化个人库，既有条目保留公开状态。尚未生成公开版本时，网站沿用原有内容。原 Markdown、参考导航导入快照和图标映射不自动删除。

生成第一个公开版本后，资源页及首页精选以该版本为准。之后在旧 Markdown/参考导航文件中的修改不会自动合并到个人库或覆盖公开版本，应在管理台编辑对应条目并重新生成版本。若临时删除公开版本文件，网站会回到原始公开目录，可能重新显示已撤下旧条目；不要将删除快照当作撤下内容的方法。

旧来源和历史导入说明见 [2026-09-05 导入报告](reports/tool-import-2026-09-05.md)。

## 导入与归档

导入保留浏览器原文件夹路径作为私人整理线索；用途分类最多两级，类型单独选择。相同网址在现有库和批次内去重，保留有意义的路径、参数和锚点；已有手写内容不被导入覆盖。

导入批次可以撤回其新增的、仍未发布的收藏，不会删除导入前已经存在的资源。归档将条目移出常规列表，仍可在已归档中恢复。
