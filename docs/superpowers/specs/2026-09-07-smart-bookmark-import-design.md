# 智能书签导入与分批整理：设计提案

日期：2026-09-07。状态：设计提案，未实施。用户已选择「自动去重并建议分类，我批量确认保留或忽略」。

## 1. 产品决定

推荐采用「导入批次 → 去重预览 → 整理建议 → 分组确认 → 私有入库」。公开发布沿用现有独立预览与确认流程。

核心目标是减少人的逐条判断量，同时保留决定权。导入 1000 条书签，应先看到一份可操作的汇总，优先处理明确的一组，其余可以下次继续。

方案比较：

| 方案 | 收益 | 局限 | 决定 |
| --- | --- | --- | --- |
| 自动去重、建议分类、批量确认 | 自动处理明确重复和机械分类，人决定收不收藏 | 需要一个保留进度的批次工作区 | 采用 |
| 全自动分类入库 | 点击最少 | 误分类和无关内容容易一起进入资源库 | 不作为默认方式 |
| 仅规则去重和手工批量操作 | 无需模型，成本与行为容易控制 | 标题含糊的书签仍需人工整理 | 保留为基础能力和降级路径 |

## 2. 现有能力与不足

现有 `bookmark-import.ts` 与 `library-domain.ts` 已做预览去重和提交时复查。比较范围包括库内所有资源（包括私有、公开、已归档）及同一批文件内的重复项。

当前通过 URL 标准化和去掉 `utm_*` 参数生成比较键；原网址仍保留。名称相同不等于重复。HTTP/HTTPS、www 与裸域、不同路径、功能查询参数及锚点均保守区分，不会将同一网站的不同文章直接合并。

代码审查发现一个漏判：删除 UTM 时参数会重新编码，`?q=a%20b&utm_source=x` 变成 `?q=a+b`，与不带 UTM 的原链接不相等。第一期应修复：去掉跟踪字段时保留其余参数的原编码、顺序与值，并补充边界测试。现有比较对象是管理库；若恢复备份后某条仅剩在公开快照中，当前导入不会额外匹配该快照独有项。

不足是只返回重复数量，缺少重复明细和处理理由；所有可导入项默认勾选，长列表一次渲染；导入预览只在弹窗内存中，关闭后不能继续原来的筛选进度；没有自动分类或网页质量判断。

当前书签文件上限 2 MB、每批最多解析 5000 条；私人库上限 20000 条且整体不超过 32 MB。第一版先在现有容量边界内改善体验，不能仅提高上限便宣称支持大批量。

## 3. 用户流程

### 上传与准备

「导入书签」仍是入口，支持浏览器书签 HTML 和每行一个网址。选择后建立一个仅所有者可访问的导入批次，显示文件名、解析数量与当前阶段。

候选项先进入独立的导入工作区，不计入「全部收藏」、公开候选或访客页面。解析、去重、生成建议和实际入库分别显示状态。用户可以跳过智能建议，直接手动筛选。

示例汇总（仅说明交互，不是用户实际数据）：

- 共解析 1000 条。
- 220 条确认重复：默认跳过，可展开查看对应旧资源或本批首次出现的位置。
- 20 条格式不支持：保留原因和可导出报告，允许修改后重检。
- 760 条候选新增：其中 540 条已有较明确的分类建议，220 条需要用户判断。

「分类建议明确」不代表资源优质或用户必须保留，不直接打价值总分。疑似重复、用途不明等都进入需确认队列，并标明具体原因。

### 分组筛选

默认打开需确认分组，同时提供「有分类建议」「确认重复」「格式问题」「全部候选」视图。原文件夹、域名、资源类型、建议分类为独立筛选条件。

每页 50 条，提供列表分页或窗口化渲染；跨页选择必须明确标为「本页 50 条」或「当前筛选结果共 N 条」。切换筛选不能静默扩大原选择范围。

批量动作：采用分类建议、指定一个分类、保留、暂不处理、忽略。忽略只改变本批决策，可以恢复；不会删除库内已有资源。未选择的候选保留在工作区，不等于忽略或删除。

支持「选择有明确分类建议的候选」作为快捷操作，再由用户确认导入数量。不会仅凭 AI 建议立即写入收藏库。

### 私有入库与续办

用户选择的候选以私有资源入库。已确认分类的条目可设为已整理，未确认分类但希望先保存的条目进入待整理；两者均不会自动成为公开候选、精选或常用。

完成界面分别显示已新增、提交时发现重复而跳过、尚未处理及失败数量。进入收藏库时默认筛选本批，便于回看。

批次保存筛选决定、已提交位置和失败项。关闭页面或断网后，重新登录可继续；重试只处理未完成项，不再创建已成功的资源。暂停和取消停止后续处理，已成功私有入库的部分明确列出。

原有「导入记录」升级为批次列表，显示处理中、待确认、部分入库、已完成、已取消、处理失败。支持继续整理与查看结果。原始 HTML 解析完成后不长期保存；结构化候选与决策保留，直到本人清理批次。

## 4. 去重与合并规则

| 类型 | 例子 | 默认处理 |
| --- | --- | --- |
| 确认重复 | 标准化后相同 URL；仅 `utm_*` 不同 | 跳过新增；展示与哪条重复及依据 |
| 疑似相同页面 | HTTP/HTTPS、www、尾斜杠或其他参数有差异 | 放入需确认；允许保留两条、关联已有、忽略本条 |
| 同站不同内容 | 同一网站的不同文章、文档、项目路径 | 独立保留，可按域名成组浏览 |
| 同用途不同工具 | 两个绘图或检索工具 | 分类到同组，供比较；不判为重复 |
| 已归档的同一 URL | 新书签指向库内归档项 | 提示「已有，已归档」；明确点击后可恢复原记录 |

强去重不移除全部查询参数或锚点，不全局将 www 与裸域、HTTP 与 HTTPS 视作同一地址。更强的站点专属规则需独立验证并记录规则版本。第一版不依赖访问目标网站才能去重。

「合并」默认关联已有记录并跳过新增。原分类、私人备注、常用、公开状态均保留；可逐字段预览是否采用新名称或补充信息，未确认字段不覆盖。来自多个书签文件夹的来源线索保存在批次记录中，避免首条胜出后丢失上下文。

同批相同 URL 使用重复组建模，每个来源条目都保留稳定 ID。组默认以首次有效条目提供名称等信息，用户可在详情中更换代表条目；列表的「保留／忽略」作用于整组，确认时一组最多新增一条。若仅排除某个来源、修正代表网址或代表失效，重新计算组关系并选择剩余有效代表，保留各来源及用户决定，不把其他来源永久丢弃。处理失败不会把整组标为完成，重试沿用该组已记录的入库结果。已成功入库的条目在批次中只读，后续编辑进入正常资源编辑流程。

重复分组变化后重新统计数量：汇总仍以原始解析条目为基数，同时明确显示去重后的候选组数，避免把来源条数误当成将新增的资源数。提交时如原本命中的库内记录已不存在，先将该组退回需确认并更新预览，不能静默跳过或自动恢复。

第一版不自动改写现有资源的身份键，不自动清理历史库中已存在的重复记录。可以展示相关已有记录，让用户处理当前导入候选。

新预览同时提示公开快照独有的匹配项为「目前公开，管理库未收录」。这类候选需要用户确认是否重新收为私有收藏，不直接与不存在的管理记录合并，也不因此改动旧公开版本。

## 5. 整理建议如何生成

先使用本系统内的规则：书签标题、原文件夹、域名及用户已有分类修正。沿用六个主分类和工具、网站、文章、素材四种类型，不让模型随意生成大量新分类。

智能建议只提供：建议类型、主分类、少量标签、用途草稿、简短依据以及确定性状态（较明确／需确认）。不能从收藏时间推断实际使用频率，也不能编造用户体验、推荐理由或价值分数。

规则无法确定时，可调用用户启用的模型能力。接入模型与对外发送数据是单独可见的功能开关：首次启用明确说明服务商、发送字段和额度；默认只提供选中条目的标题与公开站点域名，不发送私人备注、原文件夹路径、完整 URL 查询参数、内部地址或私人路径。可能含个人信息的标题提供预览并允许排除；私有／内部链接只走本系统规则或手工整理。未启用外部 AI 不阻断导入。

更准确的网页摘要或可访问性检查作为后续增强，需用户主动选择公开链接才运行。网站需要登录、反爬、超时或地域受限时显示「暂无法检查」，不自动判为无用或失效，更不删除。启用网页抓取时需独立处理内网地址限制、重定向检查、大小与超时限制；网页内容只作为资料，不能指挥工具执行动作。

用户修改过的分类优先保留，后到的建议不能覆盖人工决定。模型失败、额度耗尽或中断时保留已有建议，只重试失败项；不重复扣费式地重做整个批次。分析前显示当前选中范围和预计用量，支持取消后续处理和配置预算上限。

### 5.1 自定义 API（新增设计要求）

支持所有者自带模型服务，入口为「我的资源库 → 设置 → 智能筛选」。第一版使用一份当前启用配置，优先支持 OpenAI 兼容的 Chat Completions 协议；不承诺任意 HTTP 接口都能直接接入。只提供其他协议的服务需要增加独立适配，沿用相同的输出校验和隐私规则。

配置字段：连接名称、Base URL、API Key、模型 ID、启用开关。高级选项提供单次分析条数、并发、请求数和输出 token 上限；价格已知时可填写输入／输出单价和估算预算。模型 ID 支持手动填写，不依赖服务商一定提供模型列表接口。

例如 DeepSeek 官方提供 OpenAI 兼容格式，可通过其官方 Base URL、Key 和模型 ID 配置；实际以该接口的连接测试为准。[DeepSeek 官方说明](https://api-docs.deepseek.com/)

表单提供「保存」「测试连接」「停用」；保存不会自动发送书签。测试先展示实际目标主机、协议路径和模型，再向用户指定的服务发送固定虚构样例，验证鉴权及结构化分类结果。测试可能产生少量调用费用，不用真实书签测试。返回 200 还不够，结果必须通过本系统的分类枚举与字段校验；无法稳定返回可用结果时显示明确的兼容性提示。

普通使用时网站服务端读取已保存配置并调用接口，浏览器只提交配置 ID 和本次确认的候选范围。Key 在 Neon 私有设置中以密文保存，解密主密钥独立放在 Vercel 服务端环境变量中，不能复用登录签名密钥。Key 只在本人首次输入／替换时经过设置表单和本站服务端，保存后不回传明文，不写入 localStorage、公共前端代码、日志、资源备份或公开快照。允许替换和清除 Key；首次部署配置好加密主密钥后，后续换 API／模型只需后台保存，不用改代码或重新部署。[OpenAI 密钥处理说明](https://developers.openai.com/api/reference/overview#authentication)

自定义目标仅允许从 Vercel 可访问的公网 HTTPS 地址；拒绝 URL 内嵌凭据、内网／本机／云元数据地址，连接时验证解析目标，不跟随携带 Key 的重定向。Vercel 的 localhost 不是所有者电脑，因此仅在个人电脑运行的模型不属于第一版线上直连支持范围。

凭据绑定目标地址与配置版本；修改 Base URL 后清空旧 Key 并要求重新填写、测试，避免将旧服务凭据带给新目标。运行任务记录所用配置版本；更改配置后暂停尚未发送的小组，用户确认新目标和发送范围后才使用新版本继续，不能静默切换目的地。停用或清除 Key 同样停止后续请求。

自定义服务可能缺少价格或准确 usage。未配置价格时显示「费用未知」，使用请求数、输入大小、最大输出和并发限制；单价已知时显示估算并为并发请求预留预算，不能承诺服务商账单按估算金额精确封顶。接口超时造成结果未知时避免无限重试，提示该请求可能已计费，用户可决定是否重试。

接口失败不会影响规则去重与手工整理；不会自动改用另一服务商发送同一份数据。该能力仍属于第二期智能建议接入，基础导入流程保持独立。

## 6. 页面结构与视觉

沿用现有蓝白配色、深蓝标题及已放大的字体。主侧栏继续导航收藏；「导入记录」可直接进入未完成批次，不再增加一整套独立后台导航。

工作区顶部：批次名称、处理阶段、进度、继续／暂停。

第二行：候选新增、确认重复、格式问题、待判断的数量；需要明确区分互斥总量与候选内部的子状态，避免误相加。

主体左栏：本批原文件夹和筛选条件。主体中间：勾选框、名称／域名、建议分类、处理理由、决定。右侧按需打开详情抽屉，比较新旧条目，不常驻三栏挤压内容。

底部固定操作条：已选 N 条、批量分类、忽略、导入已选到私人收藏。小屏改为筛选抽屉和单列条目，操作条始终显示所选范围；名称及主操作 16px，辅助信息 14px，并以实际小屏检查为准。

## 7. 技术边界与分期

推荐第一期交付：重复明细、独立批次工作区、分组与批量决策、规则建议、断点继续、提交幂等与安全撤回。这一期已经解决大量导入的主要负担，无模型也完整可用。

同一流程的第二期接入外部模型建议。模型适配与数据发送开关独立于基础导入。网页摘要、联网检查和站点专属去重规则安排在以后，不扩大首期范围。

在现有 Neon 的私有命名空间新增批次及候选记录；沿用唯一所有者认证和同源保护。公开只读连接不得访问这些记录，公共快照不增加批次、建议、来源或私人字段。

去重比较、外部分析和写入是独立阶段。外部分析采用持久后台任务，小组处理、保存游标、有限重试、支持取消；不能把成千上百次外部请求塞进一个 HTTP 请求或长期占有数据库锁。

确认入库按最多 100–200 条且受请求字节上限约束的小组处理；每组事务提交前重新读取最新私人库并复查重复，关联稳定的批次／候选 ID。相同候选重复提交必须返回原结果或跳过，不产生新资源。与其他设备编辑冲突时刷新对比结果，保留本批人工决定。

当前私人库以整份 JSON 保存，分组提交仍有全库写放大；第一期需在 5000 条导入及接近现有容量上限的场景测量响应和内存。不承诺未经验证的耗时或扩大容量。若该结构不能满足验收，再单独规划资源逐行存储与数据库唯一索引迁移。

批次撤回只针对本批创建、仍私有且从未发布的资源，不影响旧资源；对导入后已人工修改的资源先列出清单，由用户单独确认，默认保留修改后的条目。已有资源的字段合并和归档恢复需单独记录撤销信息，不能被「撤回本批新增」误撤销。

## 8. 验收重点

- 本批重复、库内重复（含归档）、仅 UTM 差异正确解释；同站不同文章、功能参数及锚点不会误删。
- 解析 1000／5000 条时界面保持可操作，按页显示；人工选中范围与实际入库范围一致。
- 上传文件相同内容可识别既有未完成批次并继续；重复点击、刷新、网络超时重试不会重复写入。
- 暂停、恢复、部分失败与另一个设备同时编辑均保留进度和人工决定。
- 模型关闭或故障时基础导入可完成；人工分类优先，不向模型发送禁止字段，不生成用户推荐体验。
- 自定义接口需通过固定虚构样例测试；密钥不回显、不进公共内容或备份；改地址不会复用旧 Key，任务不会静默更换数据接收方；未知价格明确标示，有限额且超时不无限重试。
- 入库及采纳建议均不发布；忽略可恢复；撤回不影响旧资源、已公开资源和未经确认的人工编辑。
- 普通访客无法查看批次、候选、来源、分析结果及任何私有资源。

本文件只说明拟议功能和验收目标；目前线上仍是现有的预览去重、勾选导入与批次撤回流程。
