# 书签导入交互简化：先看结果，一次确认收藏

日期：2026-09-08。状态：用户已体验草稿并要求上线；正式实现及隔离验收完成，发布记录见对应验收报告。

## 发现的问题

用户明确反馈导入后的流程难理解、繁琐，智能处理不明显。现有流程要求用户辨别“采用建议、确认分类、保留、预览、私有入库”，而这些概念大多属于内部数据状态。同一件收藏操作被拆成多个动作。

代码与截图审计还发现：AI 分析入口藏在选择后的批量菜单；导航的“智能筛选”实际指向连接设置；候选行同时展示建议分类、默认分类和待确认提示；手机首屏被大标题、四个数字和解释占满，无法立即看到下一步。

只读核实线上状态：模型配置已保存密钥、通过测试并启用；当前数据库没有保留中的书签分析任务记录。连接测试并不等于对导入书签启动分析。此结论不涉及密钥、服务地址或私人书签内容，也不证明被删除的历史任务从未存在。

当前能力是：规则去重与基础分类，AI 依据用户确认发送的标题和公共域名生成分类、标签、简介建议。没有抓取或验证网页内容，因此不能把分类置信度称作“值得收藏评分”，也不能声称网站已通过可用性、质量或真实性检查。

## 方案裁决

1. **推荐：结果优先。** 上传后直接呈现整理结果，用户改少数例外，一次确认将所选资源加入收藏。AI 操作在结果页可见，对不明确的条目进一步整理。符合已选的“自动去重并建议分类，我批量确认”目标。
2. 分步向导：每屏一个动作，容易解释，但仍需反复下一步，处理大量已导入资源时成本较高。
3. 导入后自动全部入库：动作少，但将暂存、人工确认和收藏混在一起，不符合用户此前确认保留或忽略的边界。

采用第一种。默认流程为 **导入文件 → 查看整理结果 → 确认加入收藏**。外部 AI 按需单独确认发送，不自动外发。

## 用户看到的结果

- 顶部保留紧凑步骤和一句结论，例如“760 条可新增，其中 140 条需要你确认”；原始来源计数、批次管理、导出放在“整理详情”中。
- 三个主要视图：**建议收藏、需你确认、已跳过**。建议收藏表示“分类与重复关系足够明确，可以批量处理”，不是对网站价值的 AI 背书。
- 精确匹配现有收藏的书签、用户忽略、无效和排除来源归入已跳过；归档恢复、公开快照独有、疑似重复或匹配变化仍需确认，不伪装成普通可新增。新网址在同批出现 5 次时，保留 1 个可收藏资源，另外 4 条作为重复来源折叠显示，不能整组跳过。
- 计数单位明确分开：建议收藏、需确认、已收藏按去重后的“个资源”；原始书签、重复来源、无效和排除按“条书签”。已跳过详情分别列明这些来源原因。两种计数不直接相加，也不使用混合单位进度条。示例的 1000 条原始书签中，200 条均是精确匹配库内资源的重复书签，40 条无效，其余 760 条对应 760 个新资源。
- 每条只展示一套拟用名称、分类、标签和简介。修改分类直接在列表完成；来源、重复对比等低频操作在详情中。
- 页面默认展示可处理的结果列表及数量。首次加载默认选择“当前批次全部建议收藏资源”，明确显示“已选 N 个，包含其他页”，允许查看范围、取消全部和逐条取消；不能让用户误以为只选择了眼前几行。选择根据当时的明确 ID 固定，用户取消选择后不会因异步分析被静默补回。
- 需确认项只有在分类被明确设置、用户确认具体内容或匹配问题解决后，才可进入可收藏范围；AI 返回较明确分类也只能解决分类问题，不能自动绕过疑似重复、归档恢复或原匹配变化。变更后通过显式选择加入范围。
- 主动作统一为 **“将 N 条加入我的收藏”**。点击前页面已经展示本次范围、拟用分类和私有属性；一次确认同时完成采纳本次分类与私有入库，不再单独要求“采用建议”“保留”“确认分类”。
- 成功收藏的资源退出三个待处理视图，在完成结果或“整理详情 → 已收藏”中查看，不能算作已跳过。成功反馈分别显示实际新增资源数、跳过原因、失败与未处理资源数，提供“查看我的收藏”“继续处理剩余”和受保护的撤回入口。失败项仍留在需确认中。

## 智能处理如何显现

结果页直接显示 **“本批尚未进行 AI 整理”** 或最近一次真实进度，不把已连接 API 显示成书签已分析。

“AI 整理这 N 条”默认以尚不明确且可以发送的候选为范围，不要求先跨页选中再找菜单。用户也可对明确选中的范围再次分析。候选超过单次 500 上限时说明本次处理范围及剩余数量，不能显示全批已完成。

点击后仅保留一次必要的外发确认：服务、模型、发送数量、标题和域名、估算费用。详细清单可展开并排除条目；取消不会发起请求。请求上限、并发和输出 token 等参数留在配置或高级详情，默认流程使用简明提示。

分析完成后，结果自动成为同一列表中的**拟用建议**，但不覆盖人工修改，也不自动加入收藏。显示可核实的变化，例如“已补全 110 条分类建议；30 条仍需确认”，允许检查原因。不使用虚构的评分或宣传式“精选”。

如果新的分析结果增加了可推荐条目，原有固定选择保持不变，通过“选中新增 N 条”等明确操作更新本次范围。配置未启用时清楚提供设置入口，同时基础整理保持可用。

## 实施边界

保留现有 Owner 登录、独立暂存批次、保守 URL 去重、私有默认、固定选择、100 条事务分片、幂等收据、曾发布及编辑保护、AI 外发确认和未知计费不自动重试的规则。

最小后端变更是让确认预览与提交共享“拟用字段”投影：人工字段优先（包括明确清空的简介和标签），其余采用本次展示的建议；预览只读，确认哈希绑定实际字段、建议版本和资源关系，提交再次计算并在同一事务完成采纳与新增。三个视图、统计和全范围选择共享同一派生状态，不只重命名当前有重叠的筛选器。旧接口默认语义保持兼容。网络重试复用收据，不能重复新增；匹配或建议改变时要求重新核对。

已确认的大量资源按现有 100 条分片处理。关页保留成功记录和人工修改；重开明确展示尚未处理的范围并重新确认，不在后台自动执行未完成的收藏操作。本次不新增隐式自动入库队列。

独立 HTML 交互草稿使用虚构数据和模拟进度，没有外部网络请求、真实模型调用或真实资源写入。示例中的 1000、620、140 等数量只用于演示步骤和选择行为；正式管理页使用真实后端计数和持久任务。

## 验收标准

- 导入后用户无需理解“分组、候选、采纳、入库”等内部术语即可找到下一步。
- 常见收藏从结果页一次明确确认完成；不要求先采纳再保留。
- AI 状态、入口和结果变化都在默认页面可见；配置完成不被误认为分析完成。
- 手机首屏出现明确下一步，固定按钮数量与实际范围一致，无横向溢出。
- 人工修改、取消勾选和未处理条目不会被自动结果覆盖；失败可继续，已成功项不重复。
- 真实后端实现仍需针对投影一致性、重放、人工优先和批量续办补充回归；本轮草稿不能代替生产验证。
